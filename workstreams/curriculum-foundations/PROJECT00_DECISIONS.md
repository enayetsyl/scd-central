## How to use this log

1. Every decision made inside a Project 00 chat that affects Project 00's structure, contents, conventions, or canonical references gets one row.
2. Rows are added at the **bottom** in chronological order. Never reorder, never delete.
3. If a decision is later changed, do **not** edit the original row. Add a new row marked `SUPERSEDES D-PROJ00-NNN`.
4. The "Decision" cell should be a single sentence the reader can act on without context.
5. The "Reason" cell should be one or two sentences — enough that a future reader (or a future Claude instance) understands why, not just what.

## Relationship to the master decision log

Initiative-wide decisions that affect multiple Projects (D-001 through D-053 and successors) live in **PROJECT00_README.md §3**. They are *not* duplicated here.

This log holds decisions that are **Project-00-internal** — for example:
- Which version of the Bloom's primer is canonical
- When the Islamic Curation Policy moves from v0.x in Project 02 to LOCKED in Project 00
- When a Subject Spine Playbook becomes canonical
- When a canonical reference document (REF-NN) is produced, superseded, or locked
- Glossary additions, deletions, or revisions
- Changes to Project 00 folder structure or naming conventions
- Application of initiative-wide naming/convention decisions to Project 00's specific files (housekeeping records)

If a decision in a Project 00 chat would affect another Project or a standing initiative-wide rule, do **not** log it only here. Per PROJECT00_README.md §5.4 (cross-Project propagation), flag it in §"Cross-Project propagation flags" below, then propose its addition to the master README for Principal approval.

## Reopen / supersede protocol

1. **Never edit an existing row.** The log is append-only.
2. To overturn a decision, add a new row referencing the one it replaces:
   - Decision cell starts with `SUPERSEDES D-PROJ00-NNN:` followed by the new decision.
   - Reason cell explains what changed and why now.
   - Status of the old row changes from `Active` to `Superseded by D-PROJ00-MMM`.
3. If a reversal would also affect PROJECT00_README.md §3 or another Project's DECISIONS.md, flag it via §"Cross-Project propagation flags" below **before** logging.
4. If unsure whether a decision belongs here or in the master README, default to flagging it for the master README.
5. **Housekeeping decisions** (file renames applying an initiative-wide convention, version bumps of canonical references, etc.) are still logged as new rows here, since they do change Project 00's own state even if the underlying principle is unchanged.
