## Summary & Operating Checklist (read first)

**What this is.** A single, living reference that tracks how each *topic* in a subject develops across classes (Class 1 → 2 → 3 → …), so the school can decide how much emphasis each year deserves and where a topic's foundations are laid and revisited. This is *vertical alignment* — the across-classes companion to the stability analysis's across-years view.

**What it is NOT.** It is **not** a stability analysis (that is one class across 10 editions — REF-04/REF-05). It is **not** a licence to teach next year's syllabus early. The pacing principle is **"go deeper, not faster"** (see §1.4).

**What feeds it.** The completed stability *skeletons* (REF-05), not raw NCTB books. The map is a synthesis layer that sits *downstream* of stability analysis.

**What consumes it.** Subject Spine Playbooks (REF-03+), lesson-plan emphasis/pacing decisions (Project 03), and conceptually it extends REF-02 §2.6 (the per-lesson Revision Anchor) across class boundaries.

**Build order for any subject (the 8 steps — full detail in §2):**

- [ ] **1. Extract** every topic each completed class-skeleton names.
- [ ] **2. Merge** synonyms across classes into one canonical topic; assign a Topic ID + EN/BN name.
- [ ] **3. Freeze** the canonical box structure (the first mapped subject seeds the generic category headers; see §1.3).
- [ ] **4. Chain** — record each topic's rung in every class it appears (native label + source + depth).
- [ ] **5. Edges** — encode each topic's prerequisite links (what it builds on).
- [ ] **6. Score** — compute the load-bearing tier; assign the pedagogical-priority tag (§4A); raise gap flags.
- [ ] **7. Emphasis** — write the "deeper-not-faster" emphasis note per topic.
- [ ] **8. Banner** — set the subject section's completion status; date-stamp every rung.

**Maintenance checklist (each time a new analysis lands — full detail in §3):**

- [ ] Find the subject's section; add a rung to every topic the new class touches.
- [ ] Add new topic boxes only if the new class genuinely introduces a topic not already boxed.
- [ ] Re-run load-bearing scoring and gap detection for that subject.
- [ ] Date-stamp the new rungs; update the status banner; log in the version log.

# PART A — METHODOLOGY

## 1. Principles & scope

### 1.1 The two axes (why this is not a duplicate of REF-04)

| | Stability analysis (REF-04/05) | Vertical map (this REF-19) |
|---|---|---|
| Axis | One class, across **10 editions/years** | One subject, across **classes** |
| Question answered | "What is constant over time, so plans don't need yearly rework?" | "How does a topic build year to year, and where should each year's emphasis go?" |
| Input | Raw NCTB books (OCR pipeline) | Completed stability **skeletons** |
| Output unit | Per-(class,subject) skeleton + report + spreadsheet | One row per **canonical topic**, with a rung per class |

The map does **not** alter the locked build order (D-005). It is a **parallel downstream aggregation layer**: it becomes possible only after a subject's class-stack of stability skeletons exists, and it feeds the Subject Spine Playbooks and lesson-plan emphasis decisions.

### 1.2 Subjects and classes in scope

In scope = the subjects that have a stability-analysis line (REF-04 §0): **Bangla, English, Math, Science, BGS.** Classes 1–6 (current school runs 1–5; Class 6 arrives next year, then upward — the structure is built to absorb new class rungs without restructuring; see §3.3).

**Ragged start points** are normal: Science and BGS begin at **Class 3**, not Class 1. A subject's class columns start where the subject starts. Subjects outside the stability scope (ISL, ARB, ICT per D-019) are **out of scope for now**; add them only if/when they gain stability skeletons.

### 1.3 The hybrid controlled vocabulary (the make-or-break rule)

To chain a topic across classes, every class must point at the **same canonical topic**, even though each skeleton named it differently (e.g. Math: *যোগ* → *দুই অঙ্কের যোগ* → *বহু অঙ্কের যোগ ও হাতে রাখা*). We resolve this with a **hybrid** vocabulary, decided 2026-05-22:

1. **Bottom-up seed.** Build the canonical topic list from the **first subject whose class-stack is complete and scheduled for mapping** — per the current plan, **Bangla**, once Classes 3–5 land. The list is derived directly from that subject's completed skeletons, so it stays faithful to what NCTB actually contains.
2. **Freeze a stable structure.** Generalise the seed into a stable set of named topic "boxes" with lightly generic category headers (e.g. *Sound & Letter System*, *Number & Operations*, *Sentence Construction*), so the file's shape stops moving even as more analyses arrive.
3. **Sort, don't re-invent.** For every later subject/class, sort the actual topics into the existing boxes. **Add a new box only when the books genuinely demand one** (e.g. Class-6 algebra). Never delete a box — an empty box is a signal (see §5).

**Note on cross-subject seeding.** Topic *boxes* are largely subject-specific (Bangla's স্বরবর্ণ/যুক্তবর্ণ do not map onto English tenses), so in practice each subject **self-seeds bottom-up from its own complete stack**; only the light generic category headers are shared. Bangla being mapped first simply means Bangla sets those shared headers. (English's stack is already complete and could have seeded, but is deferred per D-040.)

**Topic ID format:** `{SUBJECT}-{SHORTNAME}` using D-019 subject codes — e.g. `BAN-SWARBARNA`, `BAN-JUKTOBARNA`, `MATH-ADD`, `ENG-SENTSTR`. IDs are permanent once assigned (rename the display name freely, never the ID).

### 1.4 Pedagogical guardrail — "deeper, not faster"

The map exists to inform **depth and foundation-laying**, never curriculum acceleration. Two legitimate uses, and one prohibited one:

- ✅ **Mastered early → go deeper.** If a class masters the in-year portion early, the map shows how to enrich the *same* topic (harder problems, real-world application, light foreshadowing) within the **Flex Zone** — not to start formally teaching next year's lessons.
- ✅ **Load-bearing → emphasise up front.** The map flags topics that many later topics depend on (§4). Those deserve extra in-year mastery emphasis because skipping them weakens future years.
- ❌ **Prohibited:** using the map to push a class through next year's mandated Spine content early, or to create uneven acceleration across sections. This conflicts with the school's mastery + free-thinking philosophy and the Spine/Flex model.

Every emphasis note written into the map (Step 7) must respect this guardrail.

---

### 1.5 Scope vs REF-02 within-chapter revision (v1.9, D-050 ripple)

REF-19 tracks topics **across classes** (Class N → N+1) and, within a class, **across chapters** (the topic chart's R1/R2/R3 returns are cross-chapter by construction — a topic from Chapter 3 returning at Chapter 8's weekly assignment). REF-19 does **not** describe **within-chapter** revision (session N revisits session N−1 inside one Chapter Plan, per REF-02 v1.3 §2A and the Chapter Plan's §2.9 Session Map). The within-chapter strand is REF-02's domain; the cross-chapter strand fed by this map is REF-07's. Both strands coexist; neither replaces the other. No change to any subject section, topic ID, tier, header family, or table is implied by this clarification.

## 2. Building a subject section (the 8 steps)

Run these for one subject at a time, only once that subject has ≥2 class-skeletons (one class cannot show a *progression*). Bangla, English, and Math all qualify (each has the full Classes 1–5 stack, TG-reconciled).

**Step 1 — Extract.** Open each completed class-skeleton for the subject (REF-05). List every topic/concept/skill it names, using the skeleton's own subject-dimension outputs (REF-04 §5 dimensions). Keep the native NCTB wording verbatim and note its source division (the `U{nn}` number per D-037).

**Step 2 — Merge into canonical topics.** Cluster the synonyms-across-classes into one canonical topic. Assign each a Topic ID (§1.3) and a canonical EN + BN display name. Record which native labels collapsed into it (the "aliases").

**Step 3 — Freeze the box structure.** For the first mapped subject (Bangla), the merged list *becomes* the stable box structure; generalise category headers so other subjects can reuse them. For every later subject, **reuse** the frozen headers; extend only with justification (Step 2 produced a topic that fits no existing box).

**Step 4 — Chain (record rungs).** For each canonical topic, add one **rung** per class where it appears. A rung records: class number · native label(s) in that class · source skeleton + division · **depth descriptor** (what is expected at this rung — e.g. "vowel recognition, oral" vs "vowel + consonant blending in writing") · optional stability tier inherited from REF-05 (must-preserve / preserve-if-possible / flexible) · the date the rung was added.

**Step 5 — Encode prerequisite edges.** For each topic, list the Topic IDs it **builds on** (backward edges). Forward edges (what depends on it) are *derived*, not stored. Keep edges within a subject for now; cross-subject edges are a future extension — note but don't build.

**Step 6 — Score & flag.** Compute the load-bearing tier (§4). Run gap detection (§5). Record both on the topic.

**Step 7 — Write the emphasis note.** One or two lines per topic, honouring the §1.4 guardrail: where the foundation must be solid, which rung tends to be under-served, and what "going deeper" looks like if a class is ahead.

**Step 8 — Set the banner & date-stamp.** Update the subject section's status banner (§6) to reflect how many classes are mapped; date-stamp all rungs; log in the version log.

## 3. Maintenance & growth protocol

This file is **append-and-amend** (same discipline as the CROSS_PROJECT_INDEX). It grows as analyses complete.

### 3.1 Trigger
A new (class, subject) stability skeleton is completed/locked in Project 01 and its canonical copy lands in Project 00 (REF-05).

### 3.2 Action (when a new class of an existing subject arrives)
1. Open that subject's section.
2. For every existing canonical topic the new class touches, **add a rung** (Step 4).
3. If the new class introduces a genuinely new topic, **add a box** (Steps 2–3, with justification).
4. Re-run load-bearing scoring (§4) and gap detection (§5) for the whole subject — a new rung can change a topic's downstream count and can close or open gaps.
5. Date-stamp new rungs; update the banner; log the change.

### 3.3 Action (when a brand-new class arrives next year — e.g. Class 6)
Same as §3.2. Because rungs are an **append-only ordered list**, a Class-6 rung simply appends to each topic; new Class-6-only topics get new boxes. No restructuring. The school adds one class per year — this protocol absorbs each one.

### 3.4 Action (when a brand-new subject begins production — e.g. Science)
Add a new subject section. Seed it bottom-up from its own completed skeletons (Steps 1–2), then sort into the frozen header structure where it fits (Step 3), extending only as justified.

### 3.5 Never delete
Retire a topic by marking it `RETIRED — <reason/date>`, never by deleting (preserves interpretability and gap signals). Same 60-day-minimum retention spirit as the index/glossary.

## 4. Load-bearing scoring

**Definition.** A topic is *load-bearing* in proportion to how many other topics depend on it. Once prerequisite edges exist (Step 5), this is automatic.

**Computation (per topic):**
- `dependents` = count of distinct topics that list this topic as a prerequisite (direct + indirect, i.e. follow the chain forward).
- `span` = number of classes across which those dependents are distributed.

**Tiering (starting thresholds — review after the first Bangla fill):**

| Tier | Rule of thumb | Meaning for emphasis |
|---|---|---|
| 🔴 **High (load-bearing)** | ≥4 dependents **or** dependents span ≥3 classes | Mastery non-negotiable; emphasise in-year regardless of pacing. |
| 🟠 **Medium** | 2–3 dependents | Solid coverage; revisit via Revision Anchor. |
| 🟢 **Low / terminal** | 0–1 dependents | Can flex; safe to compress if time is short. |

Thresholds are deliberately simple for v1.0 and flagged for adjustment after the first real fill shows actual distributions.

## 4A. Pedagogical-priority tag (added v1.1, 2026-05-24)

**Why this exists.** Load-bearing (§4) measures *structural* importance — how many other topics depend on this one. It is silent about a topic's importance to the **school's mission**. The first Bangla fill exposed the gap concretely: free-thinking competencies (মুক্ত রচনা, প্রশ্ন তৈরি) score 🟢 Low on dependency, so a naive "Low = safe to compress" read would target exactly the topics Instructions §6 most wants protected. The pedagogical-priority tag is a **second, orthogonal axis** that captures mission value independently of structural load.

**Values (two tiers):**

| Tag | Meaning for emphasis |
|---|---|
| 🟦 **PROTECTED** | Emphasise and protect in-year **regardless of a Low load-bearing score**. Never the first candidate to compress when time is short. |
| ◽ **Standard** | No elevation beyond the topic's load-bearing tier. (Default; the absence of 🟦.) |

**Qualifying criteria — a topic earns 🟦 PROTECTED only for a reason the load-bearing metric cannot see:**
1. **Free-thinking / self-discovery competency** — the topic is a vehicle for independent thinking, self-expression, or learner-generated work (Instructions §6: "encourage free thinking, self-discovery, and independent problem-solving").
2. **Islamic-alignment anchor** — the topic carries Universal-Core Islamic content whose under-emphasis would weaken the school's Islamic mission (school Instructions §7).

**Combined read.** Load-bearing and pedagogical-priority are read *together*: a 🟢 Low + 🟦 PROTECTED topic means "few things structurally depend on it, but protect it anyway." This is the case the single load-bearing axis got wrong.

**Discipline.** Keep PROTECTED tight — if everything valuable is tagged, the signal is lost. Tag the topic only where the structural score would actively mislead, or where the mission specifically elevates it beyond what the NCTB structure implies. Per-topic *facets* that are mission-aligned but sit inside an already-High-load-bearing topic (e.g. the generative sentence game inside `BAN-SENTENCE`) are carried in the **emphasis note**, not by tagging the whole topic.

This tag is assigned during Step 6 alongside load-bearing, and shown as a **PP column** in Table 1 and (for PROTECTED topics only) a `Pedagogical-priority:` line in Table 2.

## 5. Gap detection

Two gap types, both falling out of the structure for free:

1. **Prerequisite gap.** A topic at Class N lists a prerequisite that has **no rung at any class < N** (or whose earlier rung was dropped in the NCF redesign — cross-reference the REF-05 trend tag `Era_3_DROPPED`). Flag `⚠ PREREQ-GAP`. This is the high-value signal: it shows where students are expected to know something the curriculum never (or no longer) taught — a likely cause of silent struggle.
2. **Coverage gap.** A canonical box exists in the frozen structure but has **zero rungs** for this subject across all classes. Flag `⚠ COVERAGE-GAP` — NCTB omits or under-weights a topic the school may wish to add (a candidate for Flex-Zone enrichment, never a Spine deletion).

Each flag carries: the topic, the class(es) involved, and a one-line note. Flags are advisory inputs to the Subject Spine Playbook, not automatic curriculum changes.

#### Table 2 — Rung detail (one block per topic)

**`ENG-ALPHABET` · Alphabet & letter-sounds** — Cat A
- C1: native "Alphabet and Numbers (Unit 2)" · src `C1_ENG_Skeleton_v2`/U02 (NCF; যোগ্যতা 1.1 alphabet sounds in familiar words / 3.1 say sounds / 7.1 writing mechanics / 7.2 write letters) · depth: the **full letter-acquisition year** — recognise, sound, and form all 26 letters; NCF **non-cursive air-trace-then-write** approach · tier: 🔒 must-preserve.
- C2: native "The Alphabet, Words and Numbers (Unit 2)" · src `C2_ENG_Skeleton_v2`/U02 (NCF) · depth: review-and-consolidate, not re-teach · tier: 🟢.
- C3–C5: assumed; no standalone alphabet lesson under NCF.
- Prerequisites: none (foundational).
- Load-bearing: 🔴 **High** — every other English topic depends on it; the most load-bearing topic in the subject.
- Emphasis note: C1 foundation must be rock-solid. If a C1 class is ahead, **go deeper inside C1** (cleaner handwriting, more word-building, oral blending) — do **not** start systematic phonics or C2 work. C2 only re-anchors.

**`ENG-PHONICS` · Phonics (sound play)** — Cat A
- C1: native "Rhymes and Sounds (Unit 5)" · src `C1_ENG`/U05 (NCF; 1.1/2.1/3.1) · depth: **precursor only** — letter-sounds + rhyme-based sound awareness, not systematic phonics · tier: 🔄.
- C2: native "Let's Play with Sounds (Unit 6)" · src `C2_ENG`/U06 (NCF; **new competency** 1.1.x/3.1.x — recognise & say differences between **initial** and **final** sounds of familiar words) · depth: the **systematic phonics lesson — GENUINELY NEW in Era B** (no Era-A equivalent) · tier: 🔴 (Era-B addition).
- C3: native "Let's Play with Sounds and Numbers (Unit 4)" · src `C3_ENG`/U04 (NCF; 1.1.2/3.1.2 **middle** sounds) · depth: extends to medial sounds · tier: 🔴.
- C4: native "Sounds and Numbers (Unit 6)" · src `C4_ENG`/U06 (NCF; 1.1 stressed syllables) · depth: stress at syllable level · tier: 🟢.
- C5: teacher-side only — the TG retains phonetic-symbol guidance for the teacher; no standalone pupil phonics unit.
- Prerequisites: `ENG-ALPHABET`.
- Load-bearing: 🟠 Medium — feeds READALOUD and decoding for COMPREHENSION.
- Emphasis note: a clean ladder — letter-sounds/rhyme (C1 precursor) → **systematic initial/final** (C2, the new Era-B competency) → middle sounds (C3) → stress (C4). ⚠ Systematic phonics is **first introduced at C2** (no C1 antecedent); confirm C1 letter-sound mastery before the C2 step (see Flags `handoff`). Do not pre-teach systematic phonics in C1.

## Glossary of map-specific terms

| Term | Meaning |
|---|---|
| **Canonical topic** | The single master entry a topic is tracked under, regardless of how each class named it. Identified by a permanent Topic ID. |
| **Rung** | One class's appearance of a canonical topic, with its native label, source, and depth descriptor. |
| **Depth descriptor** | What is expected of the topic *at that class* (the qualitative "how far"). |
| **Prerequisite edge** | A "builds-on" link from one topic to another (backward only; forward is derived). |
| **Load-bearing** | How many later topics depend on this one; drives mastery emphasis (§4). |
| **Pedagogical-priority (PP)** | A second, orthogonal axis (§4A, added v1.1) capturing a topic's value to the school's mission, independent of structural load. Values: 🟦 PROTECTED / ◽ Standard. |
| **PROTECTED** | A topic tagged 🟦 on the pedagogical-priority axis: emphasise/protect in-year regardless of a Low load-bearing score. Qualifies on free-thinking-competency or Islamic-alignment grounds (§4A). |
| **PREREQ-GAP** | A topic assumes a prerequisite that was never taught earlier (or was dropped). |
| **COVERAGE-GAP** | A frozen box no class fills — NCTB omission/under-weighting. |
| **Deeper-not-faster** | The pacing guardrail (§1.4): early mastery → enrich the same topic, never accelerate into next year's Spine. |
| **Frozen box structure** | The stable set of canonical topic categories, seeded bottom-up from the first mapped subject, that all subjects sort into. |
